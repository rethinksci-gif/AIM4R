Because the supplied item contains no official announcement text, the parameter counts, license terms and capability claims here rest on the analysis summary and community reports rather than primary documentation.

hackernews · jmillikin · Sep 20, 13:09 · [Discussion](https://news.ycombinator.com/item?id=49775499)

**「Background」** Qwen is Alibaba&\#x27;s family of open-weight generative models, and the Qwen-Image line applies that approach to text-to-image generation and image editing; community members note that many earlier Qwen models shipped under permissive Apache-style licenses. Qwen-Image-2.1 is a unified generation and editing model built around a compact 7B visual generation component \(32 single-stream DiT layers\) that supports up to 2K output and as many as 10 reference images, with Day-0 ComfyUI support. **「Community discussion」** Commenters largely agreed on the model&\#x27;s strengths — native transparency, small size and, in one tester&\#x27;s words, &quot;much, much better&quot; text rendering than anything else on the open-weights market — with a prompt-to-UI developer saying the text fidelity makes it deeply interesting despite the license. The main disagreement concerned licensing: one commenter noted that earlier Qwen models used Apache and other permissive licenses while this one is more restrictive, and another asked how to run the model locally in a llama-server-style setup, a question the supplied comments do not clearly answer.

### [Hacker News Debates Pirate Face Torrent Rescue for Deleted LLM Models](https://pirateface.co/) ⭐️ 7.0/10

A Hacker News discussion centered on Pirate Face, a torrent-based service presented as rescuing deleted LLM models; the submitted link itself was thin and unverified, but commenters debated decentralized AI weight distribution and model preservation. One commenter argued there is little reason to distribute abliterated weights because orthogonalizing activations at runtime is equivalent to modifying the weights that write back to the residual stream and is computationally cheap; this approach would distribute only refusal vectors—a few thousand floats per layer—and run them against stock weights, with Antirez&\#x27;s DS4 already supporting it. Others said torrents should be the preferred method for distributing AI model weights to avoid relying on a single point of failure like Hugging Face, citing Steam and Blizzard&\#x27;s past use of torrent delivery, including StarCraft II&\#x27;s installer with seeders and leechers visualization. A further commenter described hoarding rclone copies of Hugging Face torrents and periodically checking them for bitrot, criticized Pirate Face&\#x27;s name and apparent lack of scripted torrent creation, and asked whether hosting the same content on Academic Torrents would be viable for peer-to-peer data exchange.

hackernews · skepticalgenius · Sep 20, 15:16 · [Discussion](https://news.ycombinator.com/item?id=49776699)

**「Background」** Open model weights are normally obtained from a central hub such as Hugging Face, so their continued availability depends on a single host&\#x27;s service. BitTorrent instead splits a file across many peers and verifies it by checksum, letting anyone who already holds a copy seed it; Pirate Face applies that model to permissively licensed Hugging Face models as checksum-verified torrents, advertising &quot;669k+ eligible models&quot; and the same bytes without a single point of failure. The discussion&\#x27;s &quot;uncensored&quot; angle refers to abliteration, in which a refusal direction in a model&\#x27;s hidden-state space is orthogonalized out of the weights so it answers where the aligned base refuses.

**「Impact」** For developers and users concerned about model availability, the thread points to a potential reduction in both bandwidth and dependence on Hugging Face as a single distribution point by distributing small refusal vectors for runtime activation orthogonalization instead of full abliterated model weights.

**「Community Discussion」** Commenters broadly favored torrents as a decentralized way to distribute model weights, citing game distribution as precedent, but did not agree that abliterated weights need to be torrented at all: one argued runtime activation orthogonalization is equivalent and cheaper. Practical concerns included Pirate Face&\#x27;s unhelpful name and missing scripted torrent creation, the burden of manually checking rclone copies for bitrot, and whether Academic Torrents could serve as an alternative host.

### [Decontamination Reports Can&\#x27;t Fix Benchmark Contamination, Reddit Post Argues](https://www.reddit.com/r/MachineLearning/comments/1wlimaj/why_decontamination_reports_cant_fix_benchmark/) ⭐️ 7.0/10

A Reddit post argues that decontamination reports cannot solve benchmark contamination because labs audit their own training data, cannot disclose corpora containing copyrighted works, and n-gram matching misses paraphrased, forum, GitHub, or synthetic leakage. The author cites OpenAI&\#x27;s February decision to stop reporting SWE-bench Verified and its recommendation that other labs do the same, after frontier models reproduced human-written reference fixes or verbatim problem details on some tasks and progress slowed to six points in six months. The proposed alternative is evaluator-controlled testing: submissions never receive labels, evaluation runs without network access, the evaluator builds the code from a named commit and reproduces the score, and test data is generated after submissions freeze, with only reproduced results counting. The author says they built a small version using tabular models, private test sets, and a funder-posted problem and bar, while acknowledging the argument does not prove the benchmark is good, that repeated submissions cannot squeeze a hidden test set, that the funder did not leak labels, or that a third party can re-run it without the data. The post identifies squeezing a hidden test set through repeated submissions as the gap they would close first.

reddit · r/MachineLearning · /u/NoahPersaud · Sep 20, 14:31

**「Background」** SWE-bench Verified is an open, widely used coding benchmark whose tasks and the repositories they are drawn from are both public, which makes contamination hard to avoid for model developers; in February OpenAI stopped reporting it, describing it as increasingly contaminated and recommending SWE-bench Pro instead, while Anthropic noted the tasks were specific enough to have likely entered training data. Decontamination generally means searching a training corpus for benchmark material and excluding matches, but the literature on data contamination finds such similarity- or n-gram-based methods insufficient, since paraphrased, translated, or otherwise reworded test samples can bypass them and still let a model overfit to the benchmark. The source post extends this critique to decontamination reports themselves, arguing that self-auditing, undisclosed corpora, and unmatched paraphrased or synthetic leakage keep the reports from establishing what a model was actually trained on.

**「Impact」** For labs and users who relied on SWE-bench Verified as a capability signal, the practical consequence is that reported scores can no longer be treated as trustworthy unless evaluation control moves to a third party — labels withheld from submitters, evaluation run without network access, the evaluator rebuilding the code from a named commit, and results counted only when reproduced — shifting cost and authority from model developers to benchmark operators and funders. The post itself concedes the proposal does not show the benchmark is any good, that a hidden test set cannot be squeezed through repeated submissions, that a funder did not leak labels, or that a third party can re-run it without the data.
